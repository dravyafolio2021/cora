# heyCora Content Execution System

## Objective

Attract Indian service-business owners who currently depend on WordPress and several disconnected plugins. Move qualified viewers from useful Hindi/Hinglish content into the one-month free Cora beta.

The content is not a developer diary. Every episode must explain a business problem, show a simpler Cora workflow, and invite the right owner to try it.

## One feature, one content week

Do not create a new visual backdrop every day. Complete one demo-ready product workflow, publish its feature page, and use that same page for the entire week.

Example feature page:

- Interactive feature page and live presentation: `/features/user-management`
- Product demonstration: the safe Cora beta workspace

The normal webpage remains a permanent acquisition asset. The presentation route enlarges the same story for a simple screen-shared YouTube session.

## Definition of demo-ready

A feature is ready for public content only when:

- The main customer path works.
- Safe fictional data is available.
- The exact start and finish screens are known.
- Current limitations can be explained honestly.
- The feature page matches what the beta actually does.
- The Get Started for Free destination has been tested.

## Weekly production cycle

### Day 1 — Problem

Explain how the target business handles the problem today. Mention WordPress and plugin fragmentation, but do not discuss Cora's internal architecture.

### Day 2 — Simple workflow

Use the presentation page to introduce the intended flow, then switch to the actual beta product and demonstrate the common path.

### Day 3 — Business use case

Apply the same feature to one concrete service-business situation. Stay with the same demo company and data.

### Day 4 — Advanced control

Show one deeper control or unusual case. The message is: simple by default, powerful when required.

### Day 5 — Questions and objections

Answer comments from owners. Turn repeated objections into the feature page FAQ.

### Day 6 — Feedback improvement

Show one product or explanation improvement created from audience feedback. Do not show code unless the audience explicitly requests a separate technical session.

### Day 7 — Weekly result

Show what shipped, what remains in beta, what was learned, and which businesses should apply for the free trial.

## Standard 40-minute live session

### 0–2 minutes — Hook

"Agar aap WordPress par service business chala rahe ho aur [specific problem] manage karne ke liye multiple plugins use karte ho, toh aaj ka session aapke liye hai."

### 2–7 minutes — Current problem

Use the first two presentation screens. Explain the owner’s frustration and the business consequence.

### 7–10 minutes — Cora decision

Explain the simple-first product principle. Do not describe frameworks, APIs, databases, or internal architecture.

### 10–27 minutes — Actual product demonstration

Switch from the feature presentation to the safe beta workspace. Show one complete path. Avoid unrelated settings and unfinished screens.

### 27–34 minutes — Result and limitation

Show the final state, explain what improved, and clearly state what is still being developed.

### 34–40 minutes — Customer question and CTA

Ask how viewers currently solve the problem. Invite qualified businesses to use Get Started for Free.

Continue to 60 minutes only when useful audience questions remain.

## Reusable Hinglish opening

"Agar aap WordPress par apna service business chala rahe ho aur har important kaam ke liye alag plugin manage karna padta hai, yeh series aapke liye hai. Main heyCora build kar raha hoon—service businesses ke liye ek simple all-in-one workspace. Aaj hum [problem] ko simplify karenge aur end tak working beta flow dekhenge."

## Reusable free-trial CTA

"Agar aap India mein service business chalate ho aur WordPress ke saath multiple plugins use kar rahe ho, Get Started for Free link description aur pinned comment mein hai. One-month beta ke initial users ko personally onboard kiya jayega."

## Title formula

Lead with the owner’s problem. Put the build-in-public label at the end.

`[Business problem in Hinglish] | Building heyCora Day [number]`

Examples:

- `Team Access Manage Karna Itna Complicated Kyun Hai? | Building heyCora Day 01`
- `WordPress Users Aur Permissions Ko Simple Kaise Karein? | Day 02`
- `Service Business Ke Liye Verification Workflow | Cora Beta Live`

Avoid putting React, APIs, database, coding, architecture, or WordPress development in the title.

## Screen preparation checklist

- Use one dedicated browser profile for the demo.
- Close personal tabs and disable notifications.
- Reset the fictional demo data.
- Open the feature presentation, product start screen and product result screen.
- Increase browser zoom until labels remain readable in a 1080p stream.
- Confirm no private customer information appears.
- Test Get Started for Free.
- Keep the normal feature page ready for questions and the closing CTA.

## Repurposing after each live

Create:

- One full YouTube replay
- One focused 8–12 minute video
- Three vertical clips
- One Facebook post
- One X thread
- One helpful Reddit post based on the problem

Every short-form item should send viewers to the relevant feature page, not to a generic homepage.

## What to measure

Primary funnel:

`Qualified viewer → feature page → Get Started for Free → activated beta user → paid customer`

Track weekly:

- Qualified service-business comments and conversations
- Clicks from each episode to its feature page
- Get Started for Free clicks
- Completed onboarding
- First meaningful workflow completed
- Trial-to-paid conversion
- Reasons qualified users did not continue

Views and subscribers are supporting metrics. They are not the main success measure for the first 100 customers.
